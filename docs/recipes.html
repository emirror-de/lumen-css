Application Recipes

Copy-pasteable full-page examples that compose lumen.css primitives into common production application pages. Every recipe uses only documented framework contracts — no hidden classes or one-off markup.

Each recipe shows the complete landmark and heading structure required for accessibility, identifies which application behavior is not owned by lumen.css, and cross-links to the relevant primitive documentation.

Recipe 1 — Sign-in form

A standalone authentication page with accessible field composition, inline validation, and a form-level validation summary. Suitable for a dedicated /sign-in route rendered inside the full layout shell.

Application owns: form submission, validation logic, setting aria-invalid, populating the error summary, and moving focus to the summary heading after a failed submit. See Form validation summary and Field composition primitives.

Recipe 2 — Settings page with tabs

An account settings page using the full sidebar shell and an accessible tabbed panel for Profile, Security, and Notifications sections.

Application owns: tab keyboard navigation (arrow keys, roving tabindex), toggling aria-selected and the hidden attribute on panels when switching tabs, form save logic, and validation state. See Tabs.

Recipe 3 — Records list

A production list/admin screen using the data-view shell to frame a search toolbar, results summary, sortable sticky-header table with status badges and command menus, and pagination.

Application owns: search/filter logic, sort implementation, pagination math and href construction, badge text and tone selection, row selection state, and command menu click handlers. See Data-view shell, Data tables, Pagination, and Command menu.

Recipe 5 — Notification center

A dashboard page that hosts both a persistent notification center panel in an inspector slot and a transient toast stack for real-time alerts. Shows the filled state and the empty state side by side.

Application owns: notification retrieval and rendering, unread count badge, marking items as read (removing data-unread="true"), item dismissal (removing the <li>), persistence, panel open/close (position and toggle are not owned by the framework), toast insertion/removal timing, and focus management after dismiss. See Notification center and Toast notifications.

Framework vs. Application Responsibilities

This document is the single authoritative reference for what lumen.css owns and what application code must implement for every interactive or stateful production pattern.

lumen.css is a CSS-only runtime. It styles ARIA states, data attributes, and semantic HTML. It never reads or writes DOM state, registers event listeners, or manages focus programmatically. Everything in the "Application code" column must be wired by the consuming application.

Layout shell (div[data-layout-shell])

Concern lumen.css Application code
Shell grid layout (header / sidebar / main / panel / footer) ✅ Detects variants automatically via :has() —
Sidebar off-canvas slide animation ✅ Translates sidebar when data-open is absent —
Reduced-motion sidebar transition ✅ Freezes transition when prefers-reduced-motion: reduce —
Sidebar open / close toggle — Add/remove data-open on aside[data-layout-sidebar]; manage aria-expanded on the toggle button
Sidebar overlay / scrim — Provide a backdrop element and wire its click-to-close
Panel show / hide — Include or remove aside[data-layout-panel] from the DOM
Focus management after sidebar open/close — Return focus to the trigger or move it into the opened panel

Navbar (nav[data-navbar] inside header[data-layout-header])

Concern lumen.css Application code
Desktop inline layout ✅ Rendered inline above 48em —
Grouped dropdown (hover / focus-within) ✅ Opens on :hover and :focus-within; no JS required —
Responsive collapse below 48em ✅ Collapses when aria-expanded="false" on toggle —
Navbar open state on narrow viewports — Set aria-expanded="true"/"false" on button[data-nav-toggle] on click
Escape-to-close keyboard handler — Add keydown listener to close on Escape
Roving focus / arrow-key navigation inside open panel — Implement keyboard navigation within the expanded navbar
Open-state persistence across page loads — Store and restore open state in application session
aria-current="page" on the active link — Set the attribute on the matching link for the current route

Tabs (section[data-tabs])

Concern lumen.css Application code
Active tab visual highlight ✅ Styles [aria-selected="true"] —
Active/inactive tab button appearance ✅ Derived from aria-selected —
Segmented variant appearance ✅ Applied via data-variant="segmented" —
Arrow-key navigation between tab triggers — Handle ArrowLeft / ArrowRight keydown on the tablist
Roving tabindex — Set tabindex="0" on active tab; tabindex="-1" on all others
Tab activation (focus or explicit) — Choose automatic (activate on focus) or manual (activate on Enter/Space)
Panel visibility — Toggle hidden attribute on [role="tabpanel"] elements
aria-selected state updates — Set aria-selected="true" on active tab; false on others

Command menu (details[data-menu])

Concern lumen.css Application code
Dropdown panel layout and positioning ✅ bottom-inline-end or bottom-inline-start via data-align="start" —
Menu open/close via <details> native toggle ✅ CSS-only via native details —
Outside-click dismissal — Add click listener on document to close open menus
Arrow-key roving focus inside menu — Implement keyboard navigation (optional enhancement)
Dynamic item generation — Application code generates and inserts <li> items
Action callbacks — Wire click handlers on <a> / <button> items

Form validation summary (form[data-form-errors] + [data-form-summary])

Concern lumen.css Application code
Summary block visual treatment (danger surface, heading, link list) ✅ Styled when data-form-errors is on <form> —
Field invalid-state visual reinforcement ✅ Reacts to aria-invalid="true" and :invalid —
Triggering validation — Decide when to run validation (on submit, on blur, on input)
Populating the summary link list — Generate <a href="#id"> entries for each invalid control
Focus management after failed submit — Move focus to the summary heading or the first invalid field
Setting aria-invalid on controls — The framework reacts to this attribute but never sets it
Clearing data-form-errors on success — Remove the attribute and clear the summary when errors resolve
Error message copy — All visible text is application-provided

Toast notifications (aside[data-toast-region])

Concern lumen.css Application code
Fixed top-end stack layout ✅ Positions and stacks <li> items —
Toast visual surface (tone, close button position) ✅ Via data-tone and [data-dismiss] —
role="status" / role="alert" announcement ✅ Preserved — framework never changes role —
Reduced-motion animation behaviour ✅ Entry animations respect prefers-reduced-motion —
Inserting toasts — Application code appends <li> to the <ul>
Removing toasts (dismiss button, auto-dismiss) — Application code removes the <li> on click or after timeout
Queueing and deduplication — Application code limits stack depth and deduplicates
Focus management after dismiss — Application code manages focus after the <li> is removed

Notification center (aside[data-notification-center])

Concern lumen.css Application code
Panel layout (header / list / footer) ✅ Owned —
Unread visual indicator ✅ Applied when data-unread="true" is on <li> —
Tone variant per item ✅ Applied via data-tone on <li> —
Dismiss button position ✅ Absolutely positioned in top-inline-end of item —
Notification retrieval — Application code fetches and renders <li> items
Unread count badge — Application code maintains and displays the badge
Mark-read behaviour — Application code removes data-unread="true" on interaction
Item dismissal — Application code removes the <li> on dismiss click
Persistence (read/dismissed state) — Application code stores and syncs state
Panel open / close / positioning — Application code toggles visibility (dialog, popover, off-canvas)

Pagination (nav[data-pagination])

Concern lumen.css Application code
Item layout and hit-target sizing ✅ Owned —
Current-page visual highlight ✅ Applied to a[aria-current="page"] —
Disabled previous/next appearance ✅ Applied to span[aria-disabled="true"] —
Page calculation (total pages, current index) — Application code computes and renders the correct links
href generation — Application code constructs page URLs
Disabled state decision — Application code decides when previous/next are disabled
Page-window collapsing / ellipsis placement — Application code decides which pages to show (v1 has no built-in collapsing)

Breadcrumbs (nav[data-breadcrumbs])

Concern lumen.css Application code
Item layout and CSS-only separators ✅ Owned —
Current-step highlight ✅ Applied to [aria-current="page"] —
Route generation — Application code constructs href values
Localized crumb labels — All text is application-provided
Responsive collapsing / overflow menus — Not provided in v1; application code may add

Loading patterns (progress, button[aria-busy], region [aria-busy])

Concern lumen.css Application code
Spinner and progress bar rendering ✅ Owned for all four patterns —
Reduced-motion freeze ✅ Spinner freezes at initial frame —
Toggling aria-busy — Application code sets and removes the attribute
Live-region announcement copy — Application code provides role="status" copy inside busy regions
Pairing aria-busy="true" with disabled on buttons — Application responsibility to prevent repeat submission

Field composition ([data-field], [data-field-row])

Concern lumen.css Application code
Label / control / help / error / success layout ✅ Owned —
Invalid-state visual reinforcement ✅ Reacts to aria-invalid="true" and :invalid —
Validation logic — Application code decides when a field is invalid
Marker visibility ([data-error], [data-success]) — Application code shows/hides markers at the right time
aria-invalid and aria-describedby wiring — Application code sets these attributes

Input group (div[data-input-group])

Concern lumen.css Application code
Joined visual shell (icon / prefix / control / suffix / action) ✅ Owned —
Focus, invalid, and disabled state propagation to wrapper ✅ Owned via :has() —
Search submission — Application code wires the form or button click
Clear-button behaviour — Application code resets/clears the field
Unit conversion — Suffix label is decorative; conversion is application logic
Input masking — Application code provides masking libraries

Cards (article[data-card])

Concern lumen.css Application code
Layout, spacing, border, tone styling ✅ Owned —
Media slot layout and aspect ratio ✅ Owned via figure[data-card-media] —
Navigation destination — Application code provides href on heading links
Analytics / tracking — Application code adds click handlers and data attributes
Data loading / dynamic content — Application code populates card content
Media src, alt, lazy-loading — Application code provides all media attributes

Data-view shell (section[data-data-view])

Concern lumen.css Application code
Section framing and region spacing ✅ Owned —
Loading overlay via [aria-busy="true"] on [data-data-content] ✅ Uses existing loading pattern —
Search and filter logic — Application code wires toolbar and updates content
Pagination math and link generation — Application code computes and renders nav[data-pagination]
Result count copy — All text inside [data-results-summary] is application-provided
Focus management after content updates — Application code manages focus after dynamic changes

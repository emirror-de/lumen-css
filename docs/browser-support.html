Browser Support

lumen.css targets modern evergreen browsers with a precise feature baseline. This document lists the minimum supported versions, the advanced CSS features that set those minimums, and the exact degradation behaviour when a feature is absent.

Supported browsers

Browser Minimum version Release date
Chrome / Chromium 121 Jan 2024
Edge 121 Jan 2024
Firefox 121 Dec 2023
Safari / WebKit 17.2 Dec 2023

Older releases, Internet Explorer, and legacy Edge (EdgeHTML) are explicitly unsupported and out of scope.

Feature baseline

:has() — relational pseudo-class

Used throughout lumen.css to detect layout-shell variants, navbar collapse state, icon-nav structure, and grouped-navigation dropdown triggers without requiring any modifier attribute or class on the host element.

Feature Chrome Edge Firefox Safari
:has() 105 105 121 15.4
Degradation: In browsers without :has() support, the layout-shell variant detection falls back to the eight-column grid defaulting to the widest variant (all tracks present). Navbar dropdowns do not open via hover/focus. Icon-nav structure detection is lost. The framework remains visually usable but does not adapt automatically to structural composition.

color-mix() — color interpolation function

Used in the tokens layer to derive button hover and active colors from the base tone tokens. All --color-button-*-hover and --color-button-*-active internal tokens are computed with color-mix(in srgb, …).

Feature Chrome Edge Firefox Safari
color-mix() 111 111 113 16.2
Degradation: In browsers without color-mix(), button hover/active colors fall back to the unset default (the color-mix() expression is simply invalid and the property has no value). Buttons remain functional but lack the subtle shade shift on hover and press.

Relative color syntax — rgb(from …)

Used in the tokens layer to derive the busy-region spinner backdrop color from --color-bg: 

--layout-spinner-region-backdrop: rgb(from var(--color-bg) r g b / 0.65);
Feature Chrome Edge Firefox Safari
Relative color syntax 119 119 128 16.4
Degradation: In browsers without relative color syntax, the busy-region backdrop falls back to unset (no backdrop tint). The spinner overlay still appears; only the semi-transparent background behind it is lost.

CSS cascade layers — @layer

lumen.css uses @layer reset, tokens, base, typography, controls, data, state to establish an explicit specificity ordering. Consumer overrides placed in an unlayered block always win over the framework layers.

Feature Chrome Edge Firefox Safari
@layer 99 99 97 15.4
Degradation: In browsers without @layer, the entire file is treated as unlayered, and the layer declarations are ignored. The cascade order of the rules still reflects the intended sequence (reset → tokens → … → state) because the rules are written in that order. Consumer overrides placed after the framework import still win by source order, but they do so without layer isolation, so high-specificity selectors inside the framework could win over low-specificity consumer overrides in unexpected ways.

@media (width > …) / @media (width <= …) — range media queries

Used for responsive breakpoints throughout the layout-shell and navbar sections.

Feature Chrome Edge Firefox Safari
Range media queries 104 104 63 16.4
Degradation: Browsers without range media query syntax ignore those @media blocks entirely. Layout-shell responsive behavior and navbar collapse/expand transitions are lost; the desktop layout and the always-visible navbar are shown at all widths.

position: sticky — sticky positioning

Used for the layout-shell header, footer, and sticky table headers.

Feature Chrome Edge Firefox Safari
position: sticky 56 16 59 13
Degradation: Falls back to position: static. Headers and footers scroll with content; table headers do not stay visible when scrolling long tables.

<details> / <summary> — interactive disclosure

Used for navbar grouped-navigation dropdown triggers (li > a + ul with details/summary) and command menus (details[data-menu]).

Feature Chrome Edge Firefox Safari
<details> / <summary> 12 79 49 6

All supported browser versions have had <details> support for years; this feature does not raise the minimum version.

Hard non-goals

The following browsers and environments are explicitly not supported and receive no compatibility effort:

  • Internet Explorer (all versions)
  • Legacy Edge (EdgeHTML engine, pre-Chromium)
  • Opera Mini (extreme data-saving mode)
  • Browsers that predate the feature baseline table above

Determining the effective minimum

The binding minimums for full framework support are set by the intersection of the feature table above:

  • :has() requires Firefox 121 (Dec 2023) — this is the binding lower bound.
  • The overall minimum is therefore Chrome/Edge 121, Firefox 121, Safari 17.2.

Adopters targeting slightly older releases can use the framework with the degradation notes above as the documented trade-off.
